Conversation and memory

Modern AI Systems · Lecture 7

Week 7 — From one question to a conversation

1

Main idea

The model remembers nothing.

Everything it appears to remember, the application put into its context:

  • the history of this conversation
  • memory carried over from earlier conversations
2

A conversation is a list of messages

from google.genai import types

def msg(role, text):
    return types.Content(role=role, parts=[types.Part(text=text)])

history = [
    msg("user",  "What distance does Chroma use by default?"),
    msg("model", "Chroma's unconfigured default is squared Euclidean distance [3]."),
]
reply = client.models.generate_content(
    model=MODEL,
    contents=history + [msg("user", "How do we change it?")],
    config=types.GenerateContentConfig(system_instruction=SYSTEM),
)

All of it is sent on every call. Week 2: the context window is everything the model can see.

Role names are provider-specific: Gemini user / model, OpenAI-compatible APIs user / assistant.

3

Every call re-sends every earlier turn

call 1   system │                        │ Q1
call 2   system │ Q1 A1                  │ Q2
call 3   system │ Q1 A1 Q2 A2            │ Q3
call n   system │ all n − 1 earlier turns │ Qn

6

What is measured

Each call sends three parts:

system instruction    the same on every call             not counted
history               turns 1 … n − 1                    grows with the conversation
current prompt        3 passages + task + question       changes with every question

The history can be kept in two ways:

  • Questions and answers: what was said, as on the two previous slides
  • With passages: every earlier prompt, its three passages included, and its answer

Both are counted with count_tokens on the Flash tier, for the same five turns.

8

When the history no longer fits

Each turn makes every later call longer, slower, and more expensive.

What to remove:

  • the passages of earlier turns: they were retrieved for those questions
  • the oldest turns
  • older turns, replaced by a summary of them (compaction)

A longer context can also answer worse, since earlier material competes with the current question (context rot; Week 2: context is not free).

10

Rewrite, then retrieve

history + follow-up ──► model rewrites ──► standalone question
                                                   │
          answer ◄── grounded instruction ◄── retrieval (Weeks 3–6)
REWRITE = ("Rewrite the user's last question so that it can be understood without the "
           "conversation. Keep its meaning. Reply with the question only.")

One more model call per turn. Like Week 6's router, it decides what is retrieved.

11

A rewrite can be wrong

Turn 3: "Why does the course teach that one?"

REWRITTEN   "Why does the course teach squared Euclidean distance as the
             default distance metric for Chroma?"

ANSWER      "The course uses Chroma because it offers the least operational
             overhead for a teaching setting ... [1]"

The course teaches cosine. The history never mentioned it, because turn 2 answered not stated. The rewrite can use only what the history holds.

A wrong rewrite fails silently: log the rewritten question.

12

History is not memory

Conversation historyMemory
LastsOne conversationAcross conversations
HoldsEverything saidSelected facts
WrittenEvery turnWhen the application decides
ReadWhole, on every callA profile, or what is relevant

Conversation history is not automatically useful long-term memory.

13

What is worth storing

A fact that will matter in a later conversation, not a record of this one.

Worth storingNot worth storing
The project's domainToday's question
The language of the corpusPassages already retrieved
How the user wants answers givenAnything true only today
14

The application writes memory

class Memory(BaseModel):
    facts: list[str]

EXTRACT = ("From the user's message, list the facts about the user that will still be "
           "useful in a later conversation. Leave out the question itself and anything "
           "that matters only now. Write each fact as one short sentence about the user.")

facts = llm.chat(turn, system=EXTRACT, schema=Memory).parsed.facts

Week 5's structured output, applied to a conversation turn. The code then stores each fact with the turn it came from and the date.

15

Explicit and retrieved memory

Two ways for stored facts to reach the model:

  • Explicit memory: a short profile of the user, placed in every context, whatever the question
  • Retrieved memory: a store of facts, from which each turn takes only those nearest to the current question. It is RAG over facts about the user instead of documents
# explicit: the whole profile, on every call
memory_text = "\n".join(profile)

# retrieved: Week 3's VectorStore, holding facts instead of chunks
memory = VectorStore(name="memory")
memory.add(facts)                                   # when a turn is stored
hits = memory.search(question, n_results=3)         # on every later turn
memory_text = "\n".join(h["chunk"] for h in hits)
16

Choosing between them

ExplicitRetrieved
SizeA few factsAny number
Reaches the contextOn every callWhen near the question
StrengthNever missedScales
WeaknessPaid for on every call, so must stay shortCan miss the fact that mattered
SuitsFacts almost every answer needs: the project, the corpus languageFacts needed only sometimes: an earlier decision, a past problem

A common design uses both: a short profile, and retrieval over everything else.

Retrieved memory uses the stores already built: Chroma or Neo4j.

A stale memory

Stored in Week 6: "The user is working on Lab 2." Asked in Week 8: "What should I work on this week?"

FACT ONLY        "This week, you should focus on completing Lab 2 for your Lviv
 (both runs)      tram network project. ..."

WITH WEEKS       run 1  "You should check the Week 8 course schedule for this week's
 TODAY: Week 8          specific lab or project milestone. ..."

                        Lab 3 ..."

Lab 2 was due at the end of Week 7. The date lets the model doubt the fact; only replacing it removes the error.

When memory is wrong

FailureExampleRemedy
Stale"Working on Lab 2", in Week 8Store the date; replace the fact
IncorrectAn extraction errorStore the source turn (Week 5: it reaches the answer)
IrrelevantRetrieved because it is similarRetrieve fewer; a distance threshold
UnboundedEvery turn adds factsMerge, replace, delete

A memory store needs replace and delete, not only add.
