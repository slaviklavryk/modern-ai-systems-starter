Graph RAG

Modern AI Systems · Lecture 6

Week 6 — Retrieving from a graph for a model

1

Main Idea

The user asks only a question. The system decides:

  • where the question enters the graph
  • what to retrieve from there
  • what the model reads
2

Graph RAG

Graph RAG is retrieval that passes through a graph before the model answers.

Vector RAGGraph RAG
Semantic similaritySemantic similarity + graph traversal
Good for relevant passagesGood for connected entities
Simple to buildReal modelling effort
Easy to automateNeeds meaningful design
3

Entering the graph from a question

A traversal starts at a node. A question contains words.

Three ways in:

  1. Entity vectors: embed every entity; take the nearest to the question
  2. Name matching: find the graph's names in the question
  3. Chunks, then MENTIONS: search passages by meaning; take the entities they mention
4

One graph, four retrievers

question ──► retriever ──► numbered sources ──► grounded instruction ──► answer

vector          the nearest passages                (Week 4)
by name         facts about the entities the question names
hybrid          the nearest passages + facts about everything they mention
text-to-Cypher  rows of a query the model writes

Every retriever returns sources. The answering step does not change.

5

1. Vector search on chunks in Neo4j (Week 4)

CALL db.index.vector.queryNodes('chunk_embeddings', 50, $question_vector)
YIELD node, score
RETURN node.id, node.text
ORDER BY score DESC LIMIT 3
6

2. Graph by name

Step 1. Find the entities the question names. Every entity name in the graph is reduced to its key, Week 5's kg_model.key(), and looked for in the question as whole words. No model call, no embedding.

Step 2. Return every fact that touches them, in either direction:

MATCH (e:Entity {name: $name})-[r:BUILDS_ON|USES|ASSESSES]-()
RETURN startNode(r).name, type(r), endNode(r).name, r.chunks

Each row becomes one sentence, with the chunks that state it.

Entity: a second label on every Topic, Tool and Deliverable, not a separate node.

7

Graph by name, one question

"Which parts of the course use Chroma?"

Step 1 finds one entity: Chroma. Step 2 returns its facts:

[1] Embedding uses Chroma. (stated in week-03-practical-plan.md#6)
[2] Ingest uses Chroma. (stated in week-03-practical-plan.md#6, week-03-practical.md#13)
[3] Retrieval augmented generation uses Chroma. (stated in week-03-practical.md#1)
[4] Retrieval pipeline uses Chroma. (stated in week-03-lecture-plan.md#6)
[5] Vector store uses Chroma. (stated in week-03-practical.md#1)
[6] dense retrieval uses Chroma. (stated in week-03-practical-plan.md#0)

Precise when the question names an entity. Silent when it names none.

8

3. Hybrid

question ──► 3 nearest chunks ──MENTIONS──► entities ──► their facts
                   │                                         │
                   └──────────── both go to the model ───────┘

The passages answer passage questions. The facts answer relationship questions whose entities the question does not name.

9

4. Text-to-Cypher

The first three retrievers run queries we wrote, once, for every question. A fixed query answers only the kind of question it was written for.

Here the model writes the query, for each question:

question + graph schema ──► model writes Cypher ──► run read-only
                                                         │
         answer ◄── grounded instruction ◄── rows ◄──────┘

"How many of the course's documents mention Chroma?" needs a count over the whole graph: no passage states it, and no fixed query anticipated it.

10

Each retriever has pros and cons

RetrieverSuited toFails by
VectorOne passage holds the answerUsing a wrong nearby passage, confidently
By nameA named entity's relationshipsSilence when nothing is named
HybridBoth kinds of questionInheriting errors from both
Text-to-CypherCounting and listing across the courseValid queries that miss the point

Note. Make sure to use read-only connection to Neo4J for retrieval

11

Routing - LLM chooses Retriever

class Route(BaseModel):
    retriever: Literal["vector", "name", "hybrid", "cypher"]

choice = llm.chat(question, system=ROUTE, schema=Route).parsed.retriever

The instruction describes what each retriever is for. The schema allows only the four that exist.

12

When Graph RAG is unnecessary

  • The answers sit in single passages: definitions, figures, instructions
  • The domain has no stable entities or no relationships worth traversing
  • The corpus is small enough to read, or changes faster than it can be extracted
