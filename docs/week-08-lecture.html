Tools and agents

Modern AI Systems · Lecture 8

Week 8 — From answering to acting

1

Main idea

Until now, the engineer decided every step: rewrite, retrieve, answer, store.

An agent lets the model decide the next step, after seeing what the last one returned.

It acts through tools. The model chooses; the application executes.

[[https://www.oxfordlearnersdictionaries.com/definition/english/agency]]

2

An agent

An agent is a system in which the model decides the next step at run time, after seeing the result of the previous one, and decides when the task is finished.

request ──► model ──► chooses an action ──► the application performs it
              ▲                                         │
              └────────── observes the result ◄─────────┘

            model ──► answer        when the model decides the goal is reached
3

The parts of an agent

PartWhat it isIn the course system
Goalwhat is to be achievedthe user's request and the system instruction
Actionswhat it can dothe tools
Observationswhat it learns by actingthe tools' results
Statewhat it carries between stepsthe message history (Week 7), and memory
Stoppingwhat ends the runthe model answers instead of acting, or the code stops it after n steps

The model normally stops itself, by answering. The step limit is the application's safeguard for a model that keeps acting and never answers.

Week 2   prompt ──► answer
Week 3   question ──► retrieve ──► answer

Week 7   question ──► rewrite ──► retrieve ──► answer ──► store facts

The router and the rewrite are model calls, but each decides once, before any result is seen.

6

What a model cannot do alone

The model can only write text. To act, it asks the application, through a tool.

The model lacksExampleA tool that supplies it
Current information"What is the hryvnia rate for the euro?"exchange_rate(currency)
Exact calculation48,213 × 7,906calculate(a, op, b)
Data it was not given"Which documents mention Chroma?"a query over the graph
A way to change anything"Remember that I use Docker"a write to memory

Week 2: the model knows only its training data and its context. It can often calculate by reasoning step by step, but at a cost in tokens and without a guarantee; a tool is exact.

7

A tool

A tool is a function in the application that the model may ask to have run.

The model sees three things, and never the code:

PartFor example
Nameexchange_rate
Description"The official hryvnia exchange rate set by the National Bank of Ukraine for one currency. Use it for any question about a current rate."
Parameterscurrency: a string, an ISO 4217 code such as EUR; required

The description says what the tool does and when to use it. The parameters are written as a JSON schema, as in Week 5.

8

One tool call

application ──► model      the question + the tool definitions
application ◄── model      a tool call:   exchange_rate {"currency": "EUR"}
application                runs exchange_rate("EUR")  →  "1 EUR = 50.5766 UAH, ..."
application ──► model      the same messages + the tool's result
application ◄── model      the answer:    "The NBU rate is 50.5766 hryvnias to the euro."

Two model calls. The model asks for the tool; the application runs it.

9

The messages

The tool call and its result are two more messages in Week 7's history.

role        content
user        What is the hryvnia rate for the euro?
assistant   call_1:  exchange_rate {"currency": "EUR"}
tool        result of call_1:  1 EUR = 50.5766 UAH, set by the NBU for 26.10.2026
assistant   The NBU rate is 50.5766 hryvnias to the euro.
  • The tool call is a message from the assistant; its result is a message with the role tool.
  • Each result names the call it answers, by the call's id.
  • Roles and field names differ between providers: OpenRouter uses the OpenAI-compatible format, Gemini its own (Week 9).

11

Two simple tools

ToolParametersThe function behind itSupplies
exchange_ratecurrency: a string such as EURone request to the NBU's public APIcurrent information
calculatea, b: numbers; op: one of +, -, *, /one arithmetic operationexact calculation

The function is ordinary code, and the model never sees it.

op is limited to four values by the schema (an enum), as Literal limited Week 5's types.

12

What the application does with a tool call

  1. Finds the function by the tool's name.
  2. Reads the arguments, which arrive as JSON text.
  3. Runs the function.
  4. Adds the result to the messages, marked with the call's id.
  5. Calls the model again. The model answers from the result, or asks for another tool.
13

Demonstration: the euro rate

WITHOUT TOOLS        "What is the hryvnia rate for the euro?"
                     A rate from the training data, which may be months old,
                     often given without saying so.

WITH exchange_rate   tool call   exchange_rate {"currency": "EUR"}
                     result      "1 EUR = 50.5766 UAH, set by the NBU for 26.10.2026"
                     answer      "The NBU rate is 50.5766 hryvnias to the euro."

The rate changes every working day; the training data stops at a fixed date. The tool reads the rate when it is asked. The NBU sets each rate for the next working day, hence the date in the result.

17

From router to tool choice

Week 6's router: one model call chose one retriever, before any result was seen.

With each retriever as a tool, the model chooses, and can choose again after seeing a result. The descriptions decide, as the router's descriptions did:

ToolDescription
facts_by_name"Facts from the course graph about tools, topics and labs named in the query. Returns nothing if the query names none."
search_passages"Passages from the course materials nearest in meaning to the query. Use it for explanations, reasons and procedures."

A description is a prompt. State what the tool returns and when to use it.

18

When there are many tools

  • Every definition is sent with every request: more tools cost more tokens on every call, and make the choice harder.
  • Keep the set small: each tool should serve a kind of question the system must answer.
  • With a large set, choose the few relevant to the request first, for example by embedding the descriptions and searching them as in Week 3.
19

A fixed query as a tool

documents_mentioning: "List the course documents that mention a tool, topic or lab, given its name, for example 'Chroma'."

The engineer writes one query in advance:

MATCH (d:Document)-[:HAS_CHUNK]->(:Chunk)-[:MENTIONS]->(e:Entity {name: $name})
RETURN DISTINCT d.name

The model supplies one value, $name. The query runs in Week 6's read-only transaction.

23

Agent loop - One run

An illustration, with two tools: facts_by_name and search_passages.

user      How do we change the distance metric in Chroma?

step 1    facts_by_name      {"query": "Chroma"}
          result             facts about what uses Chroma; none says how to configure it

step 2    search_passages    {"query": "set the distance metric of a Chroma collection"}
          result             passages, one with metadata={"hnsw:space": "cosine"}

step 3    answer             "Pass metadata={'hnsw:space': 'cosine'} when the
                              collection is created [1]."

The second step was chosen after the first result. No code decided it in advance.

24

Every step is a model call

  • A run of n steps makes n model calls, and each re-sends the whole history, tool results included (Week 7).
  • OpenRouter's free models allow 20 requests a minute and 50 a day per account, or 1,000 a day once 10 credits have been bought.
  • At 50 a day, a question that takes four steps can be asked about twelve times.
  • Describe the tools so that the first choice is usually right, and return results the model can use directly.
  • The step limit stops a loop that the model does not end.
25

Arguments are model output

The schema is a request to the model. The application checks the arguments before running anything, as Week 5 validated extraction.

The model sendsThe check
calculate {"a": 48213, "op": "^", "b": 7906}rejected: op must be +, -, * or /
calculate {"a": "forty", "op": "*", "b": 2}rejected: a is not a number
exchange_rate {}rejected: currency is required

Never pass the model's text to eval: a calculator built on eval runs any Python the model writes.

26

An error is a tool result

What goes wrongWhat the model receives as the tool's result
An unknown tool"Error: there is no tool 'calc'. Tools: exchange_rate, calculate."
Invalid arguments"Error: op must be one of +, -, *, /."
An unknown currency"No NBU rate for 'XYZ'."
The database is down"Error: ServiceUnavailable: could not connect to Neo4j."

The error goes back to the model as the tool's result, and the loop continues, so the model can correct the call. Week 6's text-to-Cypher already did this: a rejected query went back to the model with the database's error.
